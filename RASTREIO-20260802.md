## 1) Causa raiz: `fetchPendingActions` filtrado por `updated_at`

`loadRemoteState` fazia:

```js
const pending = await fetchPendingActions(userId, current?.payload ? current.updated_at : undefined);
```

`diario_current.updated_at` é carimbado por trigger `before update` — ou seja,
no **fim** da gravação. Mas o payload gravado foi montado **antes** do upload
começar. O diário passa de 500KB, então a janela é de segundos.

Linha do tempo que perde dado (é o caso 1 de `scripts/sync-e2e.test.mjs`):

```
18:00:00  acao B criada
18:00:00  compactToSnapshot() monta o pacote (contem A e B)
18:00:04  professor digita -> acao C criada
18:00:09  upsert termina -> updated_at = 18:00:09
          deleteActions([A, B])   <- C sobrevive, correto
proxima leitura: created_at > 18:00:09  ->  C (18:00:04) filtrada fora PRA SEMPRE
```

C fica órfã no banco: invisível para toda leitura, só recuperável por uma
`compactToSnapshot()` (que varre sem filtro de data). Foi o que restaurou os
dados do usuário nesta sessão — clicar em **Salvar** no tablet.

### Fix
Marca `actionsThrough` gravada **dentro do payload**, calculada por
`nextActionsCutoff()`: para na última ação que realmente entrou no pacote,
nunca em "agora". A leitura usa `actionsCutoff(payload)`.

Payload legado (sem a marca) → `actionsCutoff` devolve `null` → lê **todas** as
ações. Decisão deliberada: reaplicar ação já absorvida reescreve o item com o
mesmo valor (motor de patch é por id), enquanto filtrar demais esconde edição
real. Na dúvida, repetir. Isso também auto-cura as órfãs já existentes.

## 2) Corrida da compactação (pendência de 29/07, agora fechada)

`compactToSnapshot` usava o `data` da closure e terminava com `setData(merged)`
+ `suppressNextAutoSaveRef = true` — revertendo a tela e engolindo o aviso.

Fix: `dataRef` (espelho do estado, atualizado a cada render) + `resolveCompactionResult()`:
- sem edição concorrente → `setData(saved)`, auto-save suprimido (como antes);
- com edição concorrente → `setData(merge(latest, saved))` e auto-save **ligado**,
  pra diferença sair como ação nova. `hasUnsavedChanges` fica `true` de propósito.

`compactToSnapshot` agora **retorna** o outcome; `saveToSupabase` usa isso pra
não mentir "Tudo salvo" quando ainda há diferença a enviar.

## 3) Ações órfãs no caminho da mesclagem

O ramo de merge de `loadLatestFromSupabase` gravava em `diario_current` sem
apagar as ações absorvidas. Com o filtro por data isso passava despercebido;
sem ele, as ações voltariam por cima de valores mais novos.

Fix: `loadRemoteState` agora retorna `{ payload, appliedActionIds }` (mudou a
assinatura — só há 1 call site) e o ramo de merge apaga esses ids após gravar,
além de propagar `actionsThrough`. A marca é a segunda proteção se o delete
falhar.

## 4) `appendActionToSupabase` descartando salvamento (pendência de 29/07, fechada)

`if (autoSaveInFlightRef.current) return;` sem reagendar. Agora reagenda em
`AUTO_SYNC_DELAY_MS`.

## 5) UX que causava perda: o confirm do botão Salvar

`saveToSupabase` abria `window.confirm` perguntando se queria usar "um backup
existente de pasta" — e era o **Cancelar** que fazia o salvamento normal. O
usuário reportou a mensagem como incompreensível (estava certo). Pior: o OK
levava a `readLatestBackupFileFromDirectoryHandle`, que **substitui** o diário
por um arquivo antigo, sem passar pela mesclagem.

Fix: Salvar só salva. O envio de pasta virou `uploadBackupFromDirectory()`,
botão separado em Configurações, com confirmação que diz "SUBSTITUI".
Só renderiza onde `showDirectoryPicker` existe.

Achado no caminho: `saveTextFile()` existia desde sempre e **nenhum botão a
chamava** — dava pra importar backup .json e não pra exportar. Agora há
`exportBackupFile()` em Configurações.

## 6) Extração de `src/sync-engine.js`

Motivo: o motor de sync estava dentro de um componente React de 7.900 linhas,
impossível de testar em node. Movidos (sem alteração de comportamento):
`isPlainObject`, `stableStringify`, `normalize`, `normalizeHeader`,
`normalizeKey`, `DIFF_FIELD_KEYS`, `diffData`, `isPatchEmpty`, `applyPatch`,
`applyPatches`. Mais os novos `actionsCutoff`, `nextActionsCutoff`,
`resolveCompactionResult`.

⚠️ `applyPatch/applyPatches` agora recebem `migrate` por injeção (era
`migrateData` direto). Os 2 call sites em main.jsx passam `migrateData`. Chamar
sem o terceiro argumento **não migra** — é intencional pro teste, mas é pegadinha.

⚠️ `normalizeKey` alimenta 53 pontos do app (importação de planilha, casamento
de nomes, merge). Qualquer mexida ali quebra importação em silêncio. Validado
nesta sessão comparando com `git show HEAD:src/main.jsx` — idêntico.

⚠️ Ao escrever a regex de acentos no arquivo novo, ela saiu com os caracteres
combinantes **literais** (U+0300–U+036F) em vez de `\u0300-\u036f`. Mesmo
alcance, mas invisível no editor e frágil a encoding. Corrigido via script node
(`Edit` não consegue casar os literais). Se aparecer de novo, é esse o motivo.

código antigo, checar o TIPO do erro, não só o exit code.**

## Armadilhas técnicas para sessões futuras
- Herdadas e ainda válidas: SW só toca em arquivos do próprio site (rodar
  `npm run test:sw` em qualquer mexida); `IS_LOCAL_DEV` desliga o SW em
  localhost, então SW não é testável com `npm run start`; nunca usar pipe de
  texto cru do PowerShell em arquivo com acentuação.
- **Sem credencial de banco disponível para o Claude.** Só a chave publicável
  do `.env`, e o RLS a rejeita (401 confirmado nesta sessão). Não há chave
  `service_role`, não há sessão do Supabase CLI, e a extensão Claude in Chrome
  não está instalada. Verificação de dados em produção depende do usuário rodar
  SQL no painel ou conferir pelo próprio app.
- **A sessão do Supabase fica em `sessionStorage`** (decisão de 18/07): fechar a
  janela derruba o login. Por isso `loadLatestFromSupabase` roda a cada
  desbloqueio — é o que puxa a versão da nuvem.
- **`mergeBackupData` mantém o valor do aparelho local em conflito de nota.** Um
  aparelho desatualizado que mescle e reenvie pode reverter correção feita em
  outro. Não foi mexido nesta sessão; é o próximo risco real da lista.

  Não há noção de "qual edição é mais recente" por item — o patch não carrega

  avisado se a compactação de fundo falhar.
